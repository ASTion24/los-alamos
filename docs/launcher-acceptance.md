# Los Alamos：不用先管理好自己，也能开始

## 这次改变了什么

上一版已经能管理项目，却仍要求用户完成一串准备动作。真正的阻力没有完全消失：
想起一件事，先填表；想继续，先找项目、配时间、生成提案；想离开，再填写一份交接。

这次没有再扩充管理模块，而是把默认体验改成三个动作：

**先收下。只带走一件。留好下次的入口。**

“眼前一亮”不能由开发者代替用户宣布，因此本次验收以可验证的阻力减少为准，
不以页面数量、生成字数或专注分钟数作为产品价值。

## 主路径对比

| 场景 | 上一版默认路径 | 现在 |
| --- | --- | --- |
| 想起一件未完事项 | 新建项目，准备标题、事实、剩余动作等信息 | 一处输入、一次“先收下来”；不创建任务、不增加义务 |
| 开始已有项目 | 进入详情 → 驻留配置 → 生成提案 → 确认 | 首页已经展示完整边界，点击一次“确认开始” |
| 中断后回来 | 找项目和历史，再确认起点 | 首页直接显示已保存的下一动作 |
| 驻留中想起别的事 | 离开当前流程或继续在脑中记住 | 当前页面收纳；计时、项目、范围都不切换 |
| 结束一段工作 | 交接编辑器默认七项信息 | 默认两项：停在哪里、下次做什么；原有决定和材料继承 |
| 做完最后一个任务 | 返回项目，再寻找收尾决定 | 本段结束时直接出现项目收尾入口 |
| 找工作材料 | 看到一段路径，再手动寻找 | 首页/驻留/交接中的材料按钮，显式打开或定位 |

## 实现范围

- 新的“此刻”工作台作为默认首页。左侧只有本轮具体动作与边界，右侧保留未整理的挂念。
- 项目便签墙、任务图、历史、多日驻留计划没有删除，仍可从导航进入。
- 收纳箱支持待整理、先放着、已带入项目；所有状态保留原文和追加式审计。
- 准备一件事项时只确认名称、剩余动作、结束标准。只从明确的“只差”“结束标准”等表达提取建议，不装作通用自然语言理解。
- 首页预览不创建会话、不计时。开始按钮携带内容校验 token；任务、边界、约束变化后拒绝启动，必须重新确认。
- 保留提案和开始两条审计事件；重复点击、并发请求只能创建一个当前会话。
- 当前记录与下一动作保留本地草稿；页面重载不会丢失已输入的本次笔记。
- 完成页优先展示停靠点和下一入口。项目正式收尾后改为展示依据，不再催促继续。
- 主动选择文件才附加材料；点击材料才打开。未知文件类型、脚本、目录只在文件管理器定位，不执行。
- 工作界面使用稳定的浅色状态，不再每十分钟循环切换整屏昼夜颜色。
- 弹层独立于背景布局，限制背景交互和键盘焦点；快捷键不会穿透编辑弹层。
- 新能力同时提供 CLI；Agent 仍必须遵守确认规则。

## 验收场景

### A. 不想规划，只想先放下

1. 进入“此刻”，在右侧输入“旧笔记想整理成文章，但现在不必展开”。
2. 点击“先收下来”。
3. 打开收纳箱，选择“先放着”，然后从该视图取回。

预期：原文仍在；没有新增项目、任务或完成度；不要求立即选择日期和强度。

### B. 从一句话到可以开始

输入：

> 论文收尾：正文已经完成，只差核对引用；结束标准：引用全部核验通过。

收下后，在收纳箱选择“准备推进”。确认名称、剩余动作和结束标准。

预期：建议可编辑；点击“就从这里开始”只建立确认过的项目并回到首页，
不自动开工。首页显示具体动作、做到哪里、不做什么、选择依据。
点击“确认开始25分钟”才开始计时。

### C. 有分心，不必换上下文

在进行中的驻留中展开“想起了别的事”，输入一条新的挂念并收下。

预期：当前项目与会话 ID 不变；计时不会暂停；任务图和进度不变。
这条内容出现在收纳箱，并保留来自哪次驻留。

### D. 离开以后，记忆已经有人保管

1. 本次记录输入“核对到第12条引用”，重载页面。
2. 确认记录仍在，暂停并选择“部分完成”。
3. 在默认两项交接中，将第一动作改成“从第13条引用继续”，保存。
4. 点击“到这里，休息”。

预期：首页主动作就是“从第13条引用继续”；不需要打开历史。
部分完成不会按时间虚增进度。原有材料与已定事项保留。

### E. 真正做完，不再留一个中间状态

完成一个项目的最后任务并保存交接。点击“确认项目收尾”，填写交付证据后确认。

预期：无证据时不能确认；完成页显示收尾依据，主动作变为休息；
项目退出可调度集合，但历史仍可在“项目 → 已收起”查看。
暂存仍要求日期，等待仍需明确条件；不再投入不是伪装成100%完成。

### F. 开工入口不能失真

使用两个客户端或 CLI，在首页展示预览后修改任务第一动作，再尝试用旧 token 开始。

预期：旧 token 拒绝；不能在用户看过 A 之后悄悄开始 B。
低强度、计划范围、日期和每日容量限制仍生效。

### G. 材料就在入口旁边

点击首页“材料”选择本地文档，再点击它的文件名。

预期：常见文档通过系统默认应用打开；脚本只定位不执行；
不存在的文件给出错误，不打开任意替代路径；HTTP(S) 链接需用户点击。
应用不扫描文件内容，不上传材料，不替用户完成正文工作。

## 自动验收

```bash
export PATH="$PWD/.tools/node/bin:$PATH"
npm test
npm run build
.tools/py/bin/python scripts/launcher_smoke.py
.tools/py/bin/python scripts/continuity_smoke.py
```

`launcher_smoke.py` 使用真实 Electron 与隔离工作区，在 `1180×760` 和 `980×640`
验证收纳、建议确认、一键启动、分心捕获、笔记恢复、暂停、两项交接、回到入口、项目收尾。
同时断言没有偷偷创建会话、没有丢失原文、没有虚增进度。
旧流程由 `continuity_smoke.py` 回归，仍覆盖任务图、计划、分页和设置入口。

`packages/workspace/src/launcher.test.ts` 验证 token 失效、并发启动、收纳幂等转换、
任务校准不会覆盖交接、计划边界和材料目标校验。`packages/cli/src/launcher.test.ts`
验证独立进程的公开命令路径。

截图和日志在 `artifacts/launcher/`，包含 `empty`、`ready`、`prepare`、
`finish`、`return`、`released`、`long-content` 两种窗口尺寸。

## 独立体验

`scripts/seed-launcher-demo.ts` 只允许写入显式指定的空工作区：

```bash
.tools/node/bin/node --import tsx scripts/seed-launcher-demo.ts artifacts/launcher-demo
```

它创建明确标注“体验”的虚构项目、可打开的示例材料和待整理挂念，不混入个人数据。
交付预览位于 `release/launcher-preview/mac-arm64/Los Alamos.app`；
启动时使用单独工作区和用户配置目录。

```bash
open -n -a "$PWD/release/launcher-preview/mac-arm64/Los Alamos.app" \
  --env "LOS_ALAMOS_WORKSPACE=$PWD/artifacts/launcher-demo" \
  --args "--user-data-dir=$PWD/artifacts/launcher-demo-profile"
```

已有示例无需再次运行种子脚本；重新运行会拒绝覆盖。

### 五分钟体验

1. 首页直接看到“打开文稿，从第13条引用继续”，点击 `reference-check.md` 可打开虚构材料。
2. 收下一条此刻的挂念，不整理它；确认论文入口后开始一段驻留。
3. 选择部分完成，只留下停靠点和下次第一动作。休息后，首页应直接接住新入口，进度不凭时间上涨。
4. 在右侧为“体验 · 个人网站上线”确认收尾，填写“体验用验收证据”；确认后不再安排它。
5. 查看“体验 · 作品集反馈”：到期只提醒回看，不会自动恢复为今天必须做的任务。

这五步分别验收：无需先规划、无需重新找入口、离开不丢上下文、完成能够退出、
暂时做不了的事不占据当前动作。真实项目数据不参与这段体验。

## 边界

这是低阻力的注意力管理和恢复工具，不保证软件本身能消除现实中的压力或替代休息。
收纳不是承诺；一键开始仍是明确确认；“已收好”表示已本地落盘，不表示工作已经完成。
没有加入自动监视桌面、强制屏蔽软件、未经确认的文件执行、打卡积分或新的运行时依赖。
图像服务未提供可用资源，因此没有带入占位图或伪造场景图片。
macOS 预览未签名/公证。Windows/Linux 原生测试已接入 CI，但本次未执行，
不计入本机验收通过项；真实模型请求与系统钥匙串未在本次重验。
